# 通过深模块逐步分离提醒决策、同步生命周期与桌面展示

上班工具箱的主窗口同时管理提醒资格、去重、同步请求与动画，导致规则变化需要理解窗口状态，验证也容易依赖私有实现。决定保留现有 C# WinForms 单体与兼容行为，逐步将提醒决策、外部同步生命周期收进各自具有小接口的深模块：提醒模块接收明确时间和业务输入、输出决定并接收关闭反馈，同步模块拥有请求代次、有效结果和缓存合并；窗口保留绘制、动画、输入及界面线程调度。

相较一次性重写桌面框架或只拆分大文件，这一选择能在每一步交付后继续运行现有程序，并让规则通过模块接口验证；代价是迁移期需要明确旧状态与新模块的唯一所有者，禁止长期保留两套决策。仅在真实变化的 seam 引入 adapter（例如外部数据访问与可控测试实现），既有纯计算模块继续复用，不要求每个类都有接口或增加通用调度框架。

本记录是已采纳的目标设计，不表示迁移已经完成。提醒时机、补提醒窗口、优先级、关闭语义和重复规则须先由现状测试记录再迁移；纠正已确认缺陷须在工单中单独说明，不能以重构名义默改产品规则。
